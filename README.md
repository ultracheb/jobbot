# JobBot: Telegram-бот для пошуку вакансій

## Запуск (Windows: проста двойчы клікні start.bat)
1. У Telegram напішы @BotFather, `/newbot`, скапіруй токен.
2. `cp .env.example .env` і ўстаў токен (`TELEGRAM_TOKEN=`). Свой ID з @userinfobot можна ўпісаць у `ALLOWED_USERS`, каб бот адказваў толькі вам.
3. `pip install -r requirements.txt`
4. `python bot.py`

Бот працуе, пакуль запушчаны працэс. Каб ён быў 24/7, патрэбны кампутар, які не спіць, Raspberry Pi або танны VPS (`systemd`/`docker`).

## Налады ў чаце
Усё працуе па змаўчанні адразу пасля `/start` (Прага, музыка/падзеі/прадакшн, раз на 3 гадзіны). Каб змяніць, дасылай `/help`. Асноўнае: `/keywords`, `/exclude`, `/interval`, `/limit`, `/location`, `/sources`, `/quiet`, `/check`, `/pause`.

## Крыніцы
- **jobs.cz**: парсіць HTML па спасылках `/rpd/<id>/`. Калі сайт зменіць верстку, трэба падправіць `parse_jobscz` у `sources.py`.
- **Jooble**: афіцыйны API, патрэбен бясплатны ключ (`JOOBLE_KEY`).
- **RSS** (`/addfeed`) і **старонкі «kariéra»** (`/watch`): першы раз бот запамінае ўсе спасылкі, потым піша толькі пра новыя.

## Запуск на GitHub Actions (без уключанага кампутара)
Рэпа **публічнае**, як у кіно-бота: тады Actions бясплатныя без ліміту. Нічога асабістага ў рэпа няма: токен у Secrets, налады і спіс адпраўленых вакансій у Actions cache.

GitHub cron спазняецца на гадзіны, таму запуск працуе ~5.5 гадзіны запар (правярае каманды кожную хвіліну) і сам запускае наступны. Cron застаецца як запасны. Вакансіі вакансіі шукае раз на інтэрвал з налад (па змаўчанні раз на 3 гадзіны).

1. Secrets and variables → Actions → New repository secret: `TELEGRAM_TOKEN` (абавязкова), `ALLOWED_USERS` (Telegram ID праз коску, хто можа карыстацца ботам; вельмі рэкамендую, бо імя бота публічнае), `JOOBLE_KEY` (па жаданні).
2. Actions → jobbot → Run workflow для першага запуску.
3. Не запускай лакальна `bot.py` з тым самым токенам.

Калі cache прападзе (не было запускаў 7+ дзён), налады вернуцца да змаўчальных, а бот пашле бягучыя вакансіі зноў. Раз на ~30 дзён бот робіць маленькі `keepalive`-камміт, каб GitHub не выключыў расклад.
